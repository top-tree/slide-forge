# 吸收：把本地记忆的模块提升到全局仓库

`SKILL.md` 第五部分是规则，这份文档是**执行清单**与踩过的坑。

## 一、先弄清方向

```
<deck>/slide/.slide-forge/templates/t9-timeline.tex   本地记忆：锻造出来的
        │  吸收 = 逐字复制（用户点头才做，不加改动）
        ▼
~/.dsh/skills/slide-forge/evolved/templates/t9-timeline.tex   仓库：放着，不参与编译
        │  取用 = 再显式复制一次（逐字）
        ▼
<另一个 deck>/slide/.slide-forge/templates/t9-timeline.tex   又变回那个 deck 自己的一份
```

**命名规律**：`base/`、`evolved/`、`.slide-forge/` 三处都是
`styles/` + `templates/` 两个子目录，**目录项都是自包含文件**。
所以从一个地方搬到另一个地方就是"同名文件复制"，没有例外、没有拼接。

**编译只读本地记忆**（`内置 → 本地` 两层）。`evolved/` **不在编译链上** ——
这一条是踩过坑才定的：

- 曾把 `evolved/` 垫在每份 deck 底下自动加载，结果**任何一次吸收都会静默改掉
  所有已有 deck 的排版**（实测：零错误、零警告、零提示，版式却变了）
- 所以改成显式取用：**要用仓库里的模块，就复制一份进
  `.slide-forge/` 对应目录**。代价是复制一次，换来的是每份 deck 冻结得住
- **吸收不会改变任何已有 deck。** 吸收之后不必重编译任何 deck ——
  它只是往仓库里放了一份。唯一会变的是"下次取用时"拿到的东西

**结构一致、内容一致**：`evolved/templates/t9-timeline.tex` 与
`<deck>/slide/.slide-forge/templates/t9-timeline.tex` 是同一个文件的两份拷贝
（只差一行来源标注）。这就是"统一"的含义，也是不会出错的原因 ——
吸收时**逐字复制、不手改**，两份就永远对得上。

## 二、什么时候提吸收

| 时机 | 说法 |
|---|---|
| 刚在本地记忆里锻造完一个新模板 | "要吸收进全局仓库、让别的 deck 也能用吗？" |
| **某个本地模块被第二处用到**（第二个 deck，或同一个 deck 的第二页） | 主动提 —— 这是它值得吸收的硬证据 |
| 用户自己说"吸收 / 存进全局 / 以后别的 deck 也要用" | 直接做 |

问过一次，用户说不要，**就不要反复问**；等到下次复用时再提一次。

## 三、执行清单

### 1. 列出可吸收项

读 `.slide-forge/` 下的两个目录，挑出**本地独有**的文件：
（内置那份不算 —— 它本来就在 `base/` 里；和内置同名的说明是本地变体）

```
<deck>/slide/.slide-forge/templates/*.tex    每个版式一个文件
<deck>/slide/.slide-forge/styles/*.tex       每套风格一个文件
```

把清单摊开给用户挑，**不要默认全收**。

### 2. 通用性检查（吸收前唯一的关卡，别跳）

| 检查项 | 命中就建议不吸收 |
|---|---|
| 内容里有具体 deck 的东西 | 产品名、专属数据、写死的年份/人名 |
| 依赖这个 deck 本地的文件 | 指向 `figures/` 或别处本 deck 才有的路径 |
| 只在**这一页**用过 | 看不出会有第二次 |

吸收了别人也用不了，还会让仓库里多一份只对这个 deck 成立的"假通用"模块。

### 3. 查冲突（最容易出错的一步）

| 情况 | 处理 |
|---|---|
| 仓库里没有同名文件 | 正常吸收 |
| 同名、内容逐字相同 | 跳过，说一句"已经在仓库里了" |
| **同名、内容不同** | **停下来报告差异**：是同一模板的新版本（整体替换），还是另一个东西（另起名字）？ |

❌ 绝不在有差异时**静默**覆盖，也绝不做"合并"（两份混成一份必错）。

### 4. 逐字复制到仓库

```
<deck>/slide/.slide-forge/templates/t9-timeline.tex
    → ~/.dsh/skills/slide-forge/evolved/templates/t9-timeline.tex

<deck>/slide/.slide-forge/styles/dark.tex
    → ~/.dsh/skills/slide-forge/evolved/styles/dark.tex
```

**唯一的改动是加一行来源标注**：

```latex
% 吸收自 <deck 名>，2026-09-14
```

❌ **不要顺手改内容、不要"优化一下"、不要改参数** ——
吸收是**搬运**，不是编辑。内容一改，仓库那份就和本地分叉了，
下次别人取用时你无法判断哪份是对的。

**不要往 `evolved/` 里加 README、索引、说明** —— 那个目录随时可能被删空。

### 5. 验收（吸收的验收标准）

```powershell
$a = (Get-Content <本地那份> -Raw).Trim()
$b = ((Get-Content <仓库那份> | Where-Object { $_ -notmatch '^% 吸收自 ' }) -join "`n").Trim()
if ($a -ne $b) { '两份不一致 —— 回去改' }
```

**组件：两边的定义逐字相同**（只差那行来源标注）。
不一致就回去改，别交付。

### 6. 告诉用户

- 复述一遍做了什么（哪份文件、放到了哪里）
- **从现在起别的 deck 取用时拿到的是这一版**
- 本地那份**一字未动**
- 吸收**不必重编译任何 deck**（仓库不在编译链上）

## 四、吸收格式配置时的额外注意

风格文件（颜色 / 字号 / 间距）比模板危险，因为它**影响每一页**：

1. 先在**一个 deck** 里改 `.slide-forge/styles/` 里那一份，编译目视
2. 用户满意后再吸收到 `evolved/styles/`
3. **改了字号必须重新实测容量**（见 `SKILL.md` 第八部分）——
   一行能装几个字、一页能放几行都会变。把实测值一起更新进注释
4. **格式改动会自动影响所有取用了这套风格的 deck**。提醒用户这一点

## 五、用户想批量整理时

用户说"清理一下 `.slide-forge`""把 T9 改名"时：

1. 先说清这次会影响哪些**页面文件**（删模块前一定要搜命令名）
2. 删之前确认：这个 deck 里还有没有页面在用它 → 有就先改页面再删
3. **删文件后必须同步删掉 `config.tex` 里对应的 `\IfFileExists` 那一行** ——
   漏了不会报错（`\IfFileExists` 会静默跳过），但会留下一条死引用
4. 仓库里的副本要不要一并删？**问** —— 删掉 `evolved/` 里那份
   等于让**所有 deck 下次取用时**都拿不到它；只清一个 deck 的 `.slide-forge/`
   则不影响别人。两者范围差别很大，别搞错
