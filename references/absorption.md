# 吸收经验：把项目本地提升为全局

`SKILL.md` 第六部分是规则，这份文档是**执行清单**与踩过的坑。

## 一、先弄清方向

```
<项目>/slide/.slide-forge/                       锻造台 —— 自动生成在这儿
        │  吸收 = 逐字复制（用户点头才做，不加改动）
        ▼
~/.dsh/skills/slide-forge/evolved/templates/     仓库 —— 放着，不参与编译
        │  取用 = 再显式复制一次（逐字）
        ▼
<另一个 deck>/slide/.slide-forge/templates/      又变回那个 deck 自己的一份
```

**只有两层参与编译**：`内置基线 → 本 deck 的 .slide-forge/`。
`evolved/` **不在编译链上** —— 这一条是踩过坑才定的：

- 曾把 `evolved/` 垫在每份 deck 底下自动加载，结果**任何一次吸收都会静默改掉
  所有已有 deck 的排版**（实测：零错误、零警告、零提示，版式却变了）
- 所以改成显式取用：**要用仓库里的模板，就复制一份进那个 deck 的
  `.slide-forge/templates/`**。代价是复制一次，换来的是每份 deck 冻结得住
- **吸收不会改变任何已有 deck。** 吸收之后不必重编译任何 deck ——
  它只是往仓库里放了一份。唯一会变的是"下次取用时"拿到的东西

**结构一致、内容一致**：`evolved/templates/components.tex` 与
`<deck>/slide/.slide-forge/templates/components.tex` 是同一个文件的两份拷贝
（只差一行来源标注）。这就是"统一"的含义，也是不会出错的原因 ——
吸收时**逐字复制、不手改**，两份就永远对得上。

## 二、什么时候提吸收

| 时机 | 说法 |
|---|---|
| 刚在项目本地沉淀完一个新模板 | "要吸收进全局、让别的 deck 也能用吗？" |
| **某个本地模板被第二处用到**（第二个 deck，或同一个 deck 的第二页） | 主动提 —— 这是它值得吸收的硬证据 |
| 用户自己说"吸收 / 存进全局 / 以后别的 deck 也要用" | 直接做 |

问过一次，用户说不要，**就不要反复问**；等到下次复用时再提一次。

## 三、执行清单

### 1. 列出可吸收项

读这三处，把每一项摊开给用户挑，**不要默认全收**：

```
<项目>/slide/.slide-forge/templates/components.tex   每个 \Deck* / \Slide* 组件
<项目>/slide/.slide-forge/templates/format.tex       每个覆盖项
<项目>/slide/.slide-forge/pages-examples/*.tex       参考文件
```

`.slide-forge/` 里**没有登记表文件** —— 那个目录随时可能被删空，登记在
那里等于白记。项目本地模板要靠现读 `.slide-forge/templates/components.tex`
来发现。

### 2. 查冲突（最容易出错的一步）

拿本地项与全局 `evolved/` 逐项比对：

| 情况 | 处理 |
|---|---|
| 全局没有 | 正常吸收 |
| 同名、内容逐字相同 | 跳过，说一句"已经在全局了" |
| **同名、内容不同** | **停下来报告差异**：是覆盖全局、另起名（`\DeckTimelineWide`）、还是放弃？ |

❌ 绝不在有差异时静默覆盖全局 —— 全局那份可能是别的项目正在用的版本。
❌ 也绝不"顺手对齐"项目本地那份：分叉是正常状态，项目有它自己的实际情况。

### 3. 写入全局（按与 `base/` 对应的位置）

```
组件        → 追加到 evolved/templates/components.tex
格式覆盖    → 写进   evolved/templates/format.tex
参考文件    → 复制到 evolved/pages-examples/
```

**组件必须用 `\DeckDefine` 写，不要用 `\newcommand`**：

```latex
% 吸收自 <项目名>，2025-01-15
\DeckDefine{\DeckTimeline}[2]{...}
```

原因：本层之后还会加载项目的 `.slide-forge/`。项目若要覆盖这个组件，
而这里用的是 `\newcommand`，TeX 会直接报
`! LaTeX Error: Command \DeckTimeline already defined.`；
`\renewcommand` 又要求命令已存在。`\DeckDefine` 两种都吃
（= `\providecommand` 后再 `\renewcommand`），参数写法与 `\newcommand` 相同。

### 4. 登记（漏了下次就找不到）

1. **`SKILL.md` 第三部分的注册表**加一行，层填「已吸收」
   —— 这是"吸收"唯一被允许改 `SKILL.md` 的地方
2. 参考文件里若有容量上限等实测数字，补进 `references/typography.md`

**不要往 `evolved/` 里加说明文件或索引文件** —— 那个目录随时可能被删空，
说明写在 `SKILL.md` 与本文里。

### 5. 项目本地那份**保持原样**

它的页面还在 `\input` 它，删掉项目就编译不过；而且它**会覆盖**吸收来的版本
（项目本地在加载链最末），所以分叉是有意义的，不是错误。
吸收 = 往图书馆加一份，不是搬家。

**但要说清后果**：从现在起所有项目都能看到这个组件了。某个项目若不想要，
让它在自己 `.slide-forge/` 里写一份同名 `\DeckDefine` 覆盖掉。

### 6. 顺带提议升入基线（可选的第二步）

如果这个模板**通用性高、不涉及个人偏好**，可以问一句
"要不要也放进 `base/`，让干净的 skill 装完就有？"

- 用户同意 → 改动落在 `base/templates/components.tex` +
  `base/templates/style.tex`（项目拿的那份快照）+ `base/pages-examples/`，
  **三处必须同步**，否则分层副本与项目快照会不一致
- 用户没点头 → 只停在 `evolved/templates/`

## 四、吸收格式改动时的额外注意

格式覆盖（颜色 / 字号 / 间距）比组件危险，因为它**影响每一页**：

1. 先在**一个项目**里改 `.slide-forge/templates/format.tex`，编译目视
2. 用户满意后再吸收到 `evolved/templates/format.tex`
3. 吸收时同步 `SKILL.md` 第九部分的「当前配置」表 —— 这张表是全项目的默认值
4. **格式覆盖会自动影响所有项目**（不像组件只在你用到时才体现）。
   所有还在动的项目都要重编译目视：行距类改动会连锁影响行数，
   原来刚好放满的页会溢出

## 五、交付话术（吸收完要说清）

- 写进了哪些文件（路径要具体）
- 注册表加了哪几行
- 项目本地那份**没动**，以及为什么
- **从现在起所有项目都会自动带上它** —— 这一点务必说，别让用户以为只是个备份
- 有没有分叉没对齐

## 六、用户想批量整理时

用户说"清理一下 `.slide-forge`""把 T9 改名"时：

1. 先说清这次会影响哪些**页面文件**（删组件前一定要搜组件名）
2. 删之前确认：这个项目里还有没有页面在用它 → 有就先改页面再删
3. 已吸收的副本要不要一并删？**问** —— 删掉 `evolved/templates/` 里那份
   等于让**所有项目**同时失去这个组件，只清一个项目的 `.slide-forge/`
   则不影响别人。两者范围差别很大，别搞错
4. 删完同步登记：`SKILL.md` 第三部分的注册表。
   某一层删空后，那个 `.tex` 如果只剩注释就**连文件一起删掉**
